# Conversation Flows and Triage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let account administrators reserve eligible native conversations for triage and assign them to a team without exposing them to agents before transfer.

**Architecture:** Persist flows on accounts and associate each inbox with at most one flow. Reserve synchronously in the `Conversation` and incoming `Message` lifecycle, store one `ConversationFlowExecution` per conversation, and enforce its protected state through native policies, list/query filters, assignment guards, notifications, unread counts, and ActionCable recipients. Add administrator APIs and Vue pages that reuse the native conversation/message view and team assignment.

**Tech Stack:** Rails 7 / ActiveRecord, RSpec, ActionCable, Vue 3, Vuex, Vue Router, Vitest, Tailwind design system.

**Spec:** `docs/superpowers/specs/2026-11-20-conversation-triage-design.md`; user requirements are in the pasted specification supplied with the task.

## Global Constraints

- Preserve native `Conversation`, `Message`, `Inbox`, and `Team` behavior.
- Do not add Enterprise code or dependencies.
- Every query and mutation is scoped to `Current.account`.
- Agents must not access reserved conversations by list, ID, search, message, attachment, event, notification, or count.
- Reserve synchronously before post-commit event publication; do not use a routing job.
- Disable flow activation only for future reservations; existing executions remain reserved.
- A completed execution never reactivates on later messages.
- Use migrations generated by `bundle exec rails g migration` and use ActiveRecord/Arel in production paths.
- Add no user-facing strings outside backend `en.yml` and frontend `en.json`.
- Do not add `Thread.new`, monotonic clock APIs, or dependencies.

## Review Focus

- Two incoming messages racing for an unreserved conversation must converge on one execution; the reservation lock and unique conversation index must agree. Test repeated reservation and the unique database constraint in Task 1.
- A transfer error after native team assignment begins must leave the execution protected and retryable. Test rollback and a later successful retry in Task 2.
- An ActionCable job queued while a conversation is reserved must retain administrator-only recipients even if it runs after transfer. Test captured recipients in Task 4.
- A custom-role agent with broad conversation permissions must still be denied direct reads, message history, search, attachments, and counts for a reserved ID. Test each reachable boundary in Task 3.
- Disabling a flow with a reserved execution must preserve triage access; after transfer, subsequent incoming messages must follow normal behavior. Test the sequence in Tasks 1, 2, and 5.
