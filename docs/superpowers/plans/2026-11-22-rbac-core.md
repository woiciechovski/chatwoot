# RBAC Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Implement the account-scoped Rails RBAC core and administrative API without activating any of the seven business modules.

**Architecture:** Store account-owned roles and explicit grants/scopes in core models, attach a role to `AccountUser`, and keep a separate managed marker so revocation cannot fall back to legacy access. A fixed code catalog marks all seven modules as planned/non-assignable; Rails policies and transactional services protect role administration and audit it.

**Tech Stack:** Rails 7.2, ActiveRecord/PostgreSQL, Pundit, RSpec, existing API V1 conventions.

## Review Focus

- Cross-account role IDs and assignments: request must return not-found or validation error without persisting a cross-tenant link.
- Null association after explicit unassignment: managed agents must remain denied in enforced domains rather than regain legacy rights.
- Inactive roles, planned permission keys, unknown keys, and absent scopes: none may grant access.
- Two concurrent demotions/removals of the final administrators: at least one administrator remains.
- Enterprise `custom_role_id`, PlatformApp, AgentBot, SAML, and Super Admin paths: no identity inherits or overwrites another principal's RBAC state.

## Implementation Decisions

- Add `account_users.rbac_managed` alongside nullable `rbac_role_id`. `false + nil` means legacy; `true + role` means RBAC-managed; `true + nil` means explicitly unassigned and therefore deny in any future enforced domain. Assignment sets the marker; removal keeps it set. This is required to preserve the prior spec's no-fallback-on-revocation invariant.
- Store `scope_type` on each role-permission row. Because this phase supports only `all_in_account`, keeping grant and scope together prevents a permission row without its required scope. No role permission row exists without an explicit scope.
- Include `lock_version` on roles and require `expected_version` for role and grant replacement writes. A stale editor gets a conflict instead of silently overwriting newer grants.
- Expose all catalog metadata as `planned`, `assignable: false`; accept only an empty grants replacement in this phase. The seven candidate areas remain unchanged and no endpoint claims effective enforcement.
- Add a composite foreign key from `(account_users.account_id, account_users.rbac_role_id)` to `(rbac_roles.account_id, rbac_roles.id)` plus model/service checks.
- Block deletion of a global `User` while it still has an administrator membership. Its `account_users` association is async-destroyed; requiring explicit demotion/removal first avoids a race that could leave an account with no usable administrator.
